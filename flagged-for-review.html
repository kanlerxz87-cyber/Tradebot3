IRREG-01High A browser cannot open an authenticated Kalshi WebSocket: the handshake requires KALSHI-ACCESS-* headers that the WebSocket API does not allow a page to set. True sub-second streaming needs a server relay. This site polls REST every 20 s and labels the “Live · sec” chart as browser ticks. WS quick start
IRREG-02Medium Whether Kalshi sends CORS headers for browser fetch() from a GitHub Pages origin is not documented and could not be tested from this build environment. Status is “unverified”. If the browser is blocked the header says so and the snapshot is used. No key is ever required for market data. API environments
IRREG-03Medium Demo and production are separate books with separate credentials; Kalshi warns demo pricing “may not be reflective” of real markets. Market data is production. The snapshot records a measured demo/production price gap (table below). Demo env
IRREG-04Medium The public API exposes contract volume, not dollar volume. Any “$ traded” figure must be derived. Ranking uses official contract volume. The dollar column is explicitly labelled an estimate (contracts × last price). Get Markets
IRREG-05Medium Candlesticks exist only for 1, 60 and 1440-minute periods, at most 5,000 periods per request; the newest candle may lag a few seconds. Seconds-level series are built from browser polling and labelled. Backtests state their ~2-hour sample. Candlesticks
IRREG-06Low An orderbook request for an unknown ticker returns HTTP 200 with empty arrays, not 404. Emptiness is never treated as “zero liquidity of a real market”: the market record is checked separately. Orderbook responses
IRREG-07Low The request named several demo hosts. Kalshi recommends the external-api hosts but keeps the shared hosts supported. Both are documented; the site defaults to the recommended host. API environments

IRREG-26High The site said the data job “runs every 20 minutes” (README, verification page, executive summary) and “every 30 minutes” in another place. GitHub Actions actually delivered runs a median 8.8 hours apart (max 12.0 h; none under 1 h) between 2026-11-22 and 2026-11-27. Corrected everywhere to the requested cron (*/30 * * * *, best effort) plus the measured interval. The workflow now appends every run to refresh-history.json, the snapshot publishes the gaps, and the dashboard shows a snapshot-age badge (there is no page that calls an 8-hour-old snapshot “live”). refresh-history.json · GitHub: schedule is best-effort
IRREG-27Medium The “Highest-dollar live events” table was sorted by a dollar estimate that the 20-second live poll never updated — it was computed once per snapshot — while the note above it said ranking used contract volume. The sort key and the stated method disagreed. The estimate is now recomputed from the live volume_fp × last_price_dollars on every render, and the note states exactly what is sorted and that the dollar column is our arithmetic, not a Kalshi field. Get markets schema
IRREG-28High Paper positions in a settled market could never settle: the snapshot only carries open markets, so once a contract settled it disappeared together with its result field, and the auto-settlement only read that field. Found by the new executable test. Settlement now reads the market record or the resolution table, records which one answered (settlement_source), and is covered by a test that reproduces exactly this sequence. Both fields are Kalshi's own. Historical data (markets move out of live endpoints)
IRREG-29Medium The live poll compared a fresh 20-second quote against a possibly hours-old orderbook mid. That could fabricate a “≥ $0.10 swing”, and a market without a book snapshot could never raise one at all. One quote source per price now: live quote when a poll has delivered one, otherwise the snapshot. The chart header labels which source a quote came from, and a test asserts a +0.13 live move fires exactly one alert while a +0.04 follow-up fires none. Get markets · Orderbook
IRREG-30Medium The snapshot job lost whole series to HTTP 429 (128 rate-limit warnings in a single refresh) — every market, candle and alert for those series silently vanished — and every Kalshi page check in the legacy audit was also recorded as 429, so the column looked like broken links. The job now paces all requests process-wide, honours Retry-After, runs one paced retry pass and reports how many series recovered, and retries link checks separately. 429s are labelled as throttling, not as dead links. Rate limits (“back off on 429”)
IRREG-31Medium The demo-connection panel stated it required an “RSA private key”, but Kalshi's default and recommended key type is Ed25519, which Web Crypto imports under a different algorithm. It also would have rejected Kalshi's PKCS#1 RSA PEM (BEGIN RSA PRIVATE KEY), which Web Crypto cannot import directly. Both key types are now detected from the parsed key and signed correctly: Ed25519 directly, RSA with PSS-SHA256 salt 32, and PKCS#1 RSA is wrapped into the standard PKCS#8 envelope. Verified against real openssl-generated keys in the test suite. API keys: key types & signatures
IRREG-32Low Topic links were built as kalshi.com/category/<topic>. Gas prices has no such page: Kalshi files AAA gasoline contracts under Economics → Oil and energy (the series record itself returns category Economics). The demo/production spot check also sampled only the first eight rows, which were all gas contracts. Category links now come from a verified table (gas → Economics) and every one is HTTP-checked on each refresh with the status shown next to the link. The spot check samples two markets per topic. kalshi.com/category/gas-prices could not be loaded at all when checked, so it is not used. Kalshi Economics · series record (category: Economics)
IRREG-35Medium The ≥$0.10 alert feed did not say which price it measured. A candle was marked at the ask when an ask existed and at the bid otherwise, so two consecutive closes could be measured on different sides of the book. Spot-checking the published rows against Kalshi's own 1-minute candles for KXAAAGASM-26NOV30-3.50: the 10:16Z row reproduces exactly (close 0.55 → 0.68 = +$0.13) but both bars had volume_fp = 0.00, i.e. no trade printed — the move comes from quotes alone. The 09:59Z row (−$0.15) also reproduces (0.66 → 0.51) and does carry 1,672 contracts of volume. The rule is now explicit and reproducible: a candle is priced at its last trade close if the bar traded, else the mid of its closing bid and ask, else the one quote that exists — one basis per bar. Each alert publishes price_basis and a quote_only flag, both are rendered as badges in the feed, and the rule is written into snapshot.method_notes.alerts. Quote-only moves are labelled, not deleted (see live counts in snapshot.json). candles, spot-check 1 · candles, spot-check 2 · candlestick docs
